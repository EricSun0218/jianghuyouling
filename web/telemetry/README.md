# AI 使用统计

独立的私人统计看板：Vercel 提供静态页面和窄范围 API，单密码表单通过 Supabase Auth 校验指定管理员账号，
Edge Function 调用仅 `service_role` 可执行的数据库函数。不会向浏览器提供数据库管理密钥。

## 本地验证

使用 Node.js 24：

```sh
npm ci
npm test
npm run build
npm run dev
```

开发地址为 `http://127.0.0.1:18793`。开发服务器同样执行身份校验，没有本地认证绕过入口。
运行需要 `SUPABASE_URL`、`SUPABASE_PUBLISHABLE_KEY` 和 `SITE_ORIGIN` 环境变量；
这些名字可公开，实际配置及授权邮箱不要写入源码。

## 部署

1. 在独立 Supabase 项目应用 `db/schema.sql`；将 `shared/models.json` 的 ID 和标签写入 `telemetry.models`。
2. 私下设置 `telemetry.settings` 的授权邮箱和站点 Origin，为该管理员 Auth 账号配置密码。
   密码由 Supabase Auth 哈希存储，禁止放入前端、源码或日志。所有统计表开启 RLS，不给匿名或普通登录用户授予读取权限。
3. 部署 `supabase/functions/telemetry-gateway/index.ts`，连同 `shared` 文件；关闭网关 JWT 预检。
   公开上报经过严格校验，私人查询由函数内部调用 Auth `getUser` 验证令牌和已确认邮箱。
4. 登录接口只接受密码，不接受账号选择，不注册新用户，不发送登录邮件。查询时仍检查已验证的管理员身份。
   页面不从 URL 读取登录令牌，密码错误返回统一提示，沿用 Auth 的登录尝试限流。
5. 将本目录部署为 Vercel 项目，设置上述三个环境变量，绑定自有子域名并验证 HTTPS。
6. 执行 `db/verify.sql` 验证数据库统计口径；该脚本使用事务回滚测试数据，不向看板植入示例数据。

授权邮箱只保存在私人数据库配置中。普通客户端既不需要登录，也不携带私人密钥。
网页依赖许可证在 `public/third-party-licenses.txt`，更新依赖时同步更新。

## 上报与统计边界

- 每次完成一次 AI 调用，客户端异步尝试上传一次；最多 16 个同时上传请求，超出、断网或退出时可以丢失。
- 不落盘、不排队重试、不补报统计。仅在本地保留随机客户端 ID，方便跨版本去重。
- 请求只有协议版本、随机客户端 ID、事件 ID、北京时间日期、白名单模型分类、成功标记及可空的输入/输出 Token。
- 缺失用量和已知为 0 分开处理；活跃、首用和留存只由成功调用产生。
- 接受当日及前一日数据以处理午夜传输；重复事件不重复计数。去重记录保留到次日，活跃明细保留最近 120 天，汇总长期保留。
- 看板支持最近 90 天范围、结束日 DAU/连续 7 天 WAU/连续 30 天 MAU、首次/累计客户端、Token、模型分布、使用强度与成熟队列的 D7 留存。
- 客户端自报，不是防作弊计费系统；ID 不是经过验证的人数，Token 也不代表账单。
- 数据库默认最多接受 25,000 条/天、同一客户端 5,000 条/天，超出返回 429。它是数据量护栏，
  不是云平台配额保证：无效请求和查询也会消耗云服务资源，每日上限也不能替代每月免费额度检查。
  免费额度耗尽或项目暂停时允许漏报，不自动升级付费套餐。
