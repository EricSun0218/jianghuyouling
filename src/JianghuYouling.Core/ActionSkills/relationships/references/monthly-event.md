1. 已经决定明确人物与关系变化时直接调用事件行为；代码会自动批量补齐双方 relations，婚恋与春宵还会补 status，全部可靠就同轮执行。只有尚未决定对象、需要比较候选或想先理解复杂关系网时才主动查询，不要机械先查一轮。
2. event_relate/befriend 在共同经历、互助、利益结盟、救命、长期相处或彼此欣赏促成友谊时选择；sworn 在共同理想、生死考验或强烈承诺下选择；mentor 在传承、求学与关系方向自然时选择；adoptive_parent 表示行动者认目标为义父/义母，adoptive_child 表示行动者收目标为义子/义女，只在长期照料、依靠、救命恩情或视若亲子的前情成熟时选择。年龄、双方好感以及是否已有在世父母或子女不是硬门槛；重复义亲和本体判定冲突的血亲、继亲、结义、婚恋等关系仍不能建立。lover 在行动者因性取向、欣赏、依恋和经历产生单向爱慕时选择。NPC 之间可自主发展关系；涉及太吾时只允许 NPC 向太吾单方面表达爱慕，结交、结义、师徒、义亲、成婚和春宵都不能由过月事件替太吾同意。已存在的同类关系不能重复建立。
3. event_enmity(make=true) 在背叛、羞辱、伤害、欺骗、争夺、威胁、嫉妒、原则冲突或利益冲突升级时选择；make=false 在道歉、报恩、共同危机、调解、误会澄清或交易和解时选择。刚正者可因惩戒恶行结仇，唯我者可因财富、地位、宠爱或亲密关系受损结仇，但都要承接本回具体事实。
4. event_favor 用于本回经历只改变行动者的观感、尚不足以建立或解除正式关系时；不能替代正式关系，也不与同一件事的关系变化重复放大。
5. event_matchmake 在双方情意、承诺与前情已经发展到愿意结合时选择；event_spend_night 在双方成年、情愿、已有亲密关系或足够情意且本回自然发展到亲密互动时选择；不得把婚恋当作凑关系类别的快捷动作。
6. event_dissolve 在背叛、原则冲突、失望、利益决裂、义亲或师徒反目、感情终结或人物主动斩断旧牵连时选择，且只能解除真实存在的关系；义亲按行动者看目标的辈分填写 adoptive_parent/adoptive_child。
7. 自动预检不满足时动作没有发生，应换成其它关系后果或行动；真实派发后明确失败才进入故事余波。根据权威原因换人物、关系种类或行动，不能连续尝试同类关系碰运气。
