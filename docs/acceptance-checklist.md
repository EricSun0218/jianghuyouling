# 《江湖有灵》全 Mod 端到端发布门禁

本清单覆盖当前 Mod 的全部公开功能和关键恢复路径，不以“本轮新增功能”作为边界。任何源码字符串断言只能防止接线漂移，不能单独证明端到端通过。

## 证据等级

- **U（离线行为）**：DevTest 对真实业务类型、协议 fixture、边界和负路径执行断言。
- **I（集成）**：本地模拟 provider 或真实测试接口贯通序列化、HTTP/SSE、工具循环和回执。
- **F（故障恢复）**：在超时、丢包、截断、损坏、并发、取消和重启条件下验证恢复语义。
- **G（游戏内）**：在已备份的可恢复存档中通过真实 UI、前后端 ModDomain RPC 和游戏原生状态验证。
- **D（发布）**：Debug/Release 构建、部署哈希、启动日志、秘密扫描和文档版本一致。

发布报告必须为每个编号记录 PASS/FAIL、证据等级、时间、日志标志或产物路径。`SKIP` 只能用于未进入发布候选的调查记录；最终发布门不接受任何 `SKIP`，权威游戏前置无法构造时也必须先补足可复现测试条件，不能以“没时间/不方便”跳过。

### 门禁分层与机器可读证据

- `tools/full-mod-e2e.ps1` 是为旧命令保留的 **automated preflight**：它只证明构建、回归、协议 fixture、权威反编译和部署哈希等自动门禁通过，不能单独把任何实机清单项记为通过，也不得在发布报告中称为“全 Mod E2E”。
- `tools/new-real-game-e2e-manifest.ps1` 只生成逐项 `PENDING` 模板，不会备份、恢复或修改存档；模板输出被限制在工作区 `.e2e-results`。
- `tools/e2e/protect-real-game-data.ps1` 是唯一允许改动真实测试数据的辅助脚本。`Backup` 与 `Restore` 必须分两次显式调用；两次都会确认太吾前端和 `GameData` 后端已关闭、路径位于明确父目录、源/目标不重叠且全树没有 junction/symlink/reparse point。备份清单 v2 逐文件记录规范化相对路径、长度、SHA-256，并记录空目录；恢复先在游戏目录同卷 staging 中完整读回，再交换目录，最后删除测试数据隔离目录和 `backup-data` 副本。
- `tools/e2e/new-secret-scan-report.ps1` 从实际字节生成秘密扫描报告 v2。它在内存中解开当前 Windows 用户的 `llm.json`、`tts.json`、`minimax.json` main/bak/tmp DPAPI 凭据，对六个范围同时执行通用模式和 exact-value 扫描；报告只记录输入文件/对象哈希与计数，不写入、输出或指纹化密钥值。
- `tools/verify-real-game-e2e-evidence.ps1` 是只读的真实游戏全 Mod E2E 最终证据门。它从本清单逐行提取全部 `E2E-xxx` 与 `E2E-Txx` ID，要求 manifest 中恰好各有一个 `PASS` 条目；`FAIL`、`PENDING`、`SKIP`、缺失、重复和未知 ID 均失败。
- 每项证据必须给出证据等级、UTC 时间、实际产物路径、匹配的 SHA-256、精确 locator（如日志行、视频时间点或截图区域）及具体观察；同一“产物 + locator”不得跨编号复用，空泛的 `PASS/OK/works` 不构成证据。
- 最终门还会核对干净工作树对应的完整 Git SHA、Steam buildid、已安装程序集与本地反编译权威哈希、最新 Player.log、Release 产物清单和秘密扫描报告。恢复校验不依赖已删除的备份树：验证器从不可变备份清单的逐文件行重算树哈希，再直接与恢复后的 `SaveGames`、`TaiWu-JianghuYouling-Logs` 比较，并要求 `backup-data` 已不存在。证据必须在默认 72 小时时效窗内。
- 秘密扫描必须恰好覆盖 repository、完整 Git blob 历史、与 manifest 同目录的 `command-output`、该轮 `Player.log` 及存在时的 `Player-prev.log`、`%LOCALAPPDATA%\JianghuYouling\llm_metrics.jsonl` 及存在时的 `.1` 轮转文件、游戏 ModLogs 下全部 `Exports` 目录；六范围输入集合、每文件/Blob 哈希和 exact DPAPI 凭据数量由最终门独立重算，`findings` 必须为 0。声明六个范围名称的手写模板不能通过。
- `tools/test-real-game-e2e-evidence-gate.ps1` 只在 `.tmpbuild` 中执行 19 个正反 fixture：真实临时 backup→修改→restore→删除副本、manifest-only 最终通过、删除最终报告后的 manifest-only 恢复发布、清理中断后自动收敛、会话越界、错误独立 manifest 哈希、测试期凭据轮换拒绝、残留副本、恢复后篡改、路径穿越、虚假清理、手写秘密报告、六范围 exact-key/通用模式正负扫描、仅在 `Player-prev.log` 或 `.1` 指标文件泄露、全缺失、重复、未知、伪证据和伪 locator；清理前再次验证绝对路径仍位于临时根下。
- 完整操作顺序和命令见 `docs/real-game-e2e-data-safety.md`。任何一步失败都必须保留清单和备份副本排障，不得手工把状态改为 `PASS`。
